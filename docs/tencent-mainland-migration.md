# 植藏：腾讯云大陆部署准备

更新时间：2026-10-20。用户已选择大陆备案、长期使用，尚未购买服务器或注册域名，先按腾讯云准备。

本文件是迁移方案及购买清单，不是可直接运行的部署包。目前尚未完成腾讯云运行适配、账号迁移或数据迁移，也未切换线上网站。

## 购买与备案顺序

1. 注册腾讯云中国站账号，完成实名认证。备案主体、域名持有人及实际网站运营者应保持一致；个人或单位备案按实际情况选择。
2. 注册域名并完成域名实名认证。域名可以稍后购买，但提交备案申请前必须准备好；实名信息同步也需要时间。
3. 购买符合备案条件的中国大陆服务器。在控制台确认实例可以用于备案，核对首次购买价、续费价、流量及备份费用。
4. 通过腾讯云备案系统提交真实的网站信息和材料，完成接入商及管局审核。身份材料与核验由账号所有者在官方流程中提交。
5. 开发及封闭测试可与备案并行；备案通过后，完成域名解析、HTTPS、登录配置和最终数据迁移，再开放域名访问。

腾讯云当前文档要求轻量应用服务器为中国大陆地区、包年包月，购买时长至少 3 个月（含续费），备案期间剩余有效期至少 1 个月，并具备符合要求的大陆公网 IP 和非零带宽。购买前以备案控制台的实际资格检查为准。

## 建议的初期配置

以下是按小规模植物档案站点给出的容量建议，不是厂商固定套餐或性能保证；价格与库存以购买页为准。

| 项目 | 建议 |
| --- | --- |
| 应用服务器 | 腾讯云轻量应用服务器 Lighthouse；若套餐不合适，可选 CVM |
| 地域 | 中国大陆；根据主要使用者位置选择华东、华南或华北，照片存储同地域 |
| 系统 | Ubuntu LTS 纯净系统 |
| CPU / 内存 | 2 核 / 4GB 起步，迁移后实测再调整 |
| 系统盘 | 约 80GB 起步；个人照片不长期只存系统盘 |
| 公网 | 实例具备备案支持的公网 IP；约 3–5Mbps 起步，核对月流量额度 |
| 购买时长 | 满足备案条件；长期使用可比较一年费用及续费价格 |
| 照片 | 同地域 COS 私有存储桶，按实际存储与访问量计费 |
| 初期其他资源 | 暂不需要另购 CDN、负载均衡或大型托管数据库 |

域名可以与服务器在同一腾讯云账号管理，减少后续配置环节。当前没有确定域名、地域、套餐、备案主体或预算，也未产生采购操作。

## 已确认的项目适配工作

| 当前实现 | 大陆部署需要完成的工作 |
| --- | --- |
| `worker/index.js` 是 Cloudflare Worker，构建产物导出 `fetch`，没有普通 Node HTTP 启动服务 | 增加 Node HTTP 入口、请求/响应适配、生产进程管理及 HTTPS 反向代理 |
| D1 通过 `env.DB.prepare(...).bind(...)` 访问 SQLite | 初期可使用持久化 SQLite 并适配 D1 调用，验证并发版本保护；随规模增长再评估托管数据库 |
| R2 通过 `env.BUCKET.put/get` 保存和读取照片 | 接入 COS 服务端 SDK；保持原有对象键与访问权限语义 |
| `worker/auth.js` 仍支持原 Sites 的身份头 | 独立部署必须关闭 `TRUST_SITES_IDENTITY`，不能信任客户端提交的用户身份头 |
| 微信后端已有部分实现，但 `public/app.js` 明确隐藏并禁用微信登录入口 | 需要选定并完成可用的独立登录方式；不能把现有代码当作已开通微信登录 |
| 旧拥有者使用 Sites 账号标识，新微信账号按另一套标识建立 | 通过已验证身份制定明确的账号绑定/迁移映射，不按首次登录自动认领旧档案 |
| `public/style.css` 从 Google Fonts 远程导入字体 | 大陆版本改用系统字体或本地字体，清理关键路径上的境外依赖 |
| GitHub 仅保存源码，目前没有自动部署流程 | 以可重现发布包部署到服务器；若服务器访问 GitHub 不稳定，在构建端生成包后传入服务器 |

建议初期目标为：大陆服务器运行应用和 SQLite，COS 私有桶保存照片，浏览器通过同站点 API 访问个人数据。此方案尚待实现与测试，当前 `npm run dev` 仍是 Wrangler 开发环境，不能作为腾讯云生产服务。

登录方式需要单独落实。账号密码、短信、微信各有实施和开通条件；备案完成不代表微信登录已获得权限。微信方式以对应开放平台/公众号实际资格和后台开通结果为准。

## 数据迁移范围

- 植物档案及日志：`plants`，包括原始 `owner`、记录 ID、版本和照片引用。
- 分类树：`taxa`，包括独立分类节点和分类参考图引用。
- 图片归属：`images` 表，以及 R2 中对应的图片对象和 MIME 信息。
- 身份关联：`wechat_identities` 及确认过的原账号映射；不直接继承旧会话，迁移后重新登录。
- 静态资源：全部 83 张开屏标识、示例照片及授权说明、分类页面和桌面安装资源。

必须从原网站取得当时最新的完整数据库与对象快照。仓库 `backups/personal/` 是历史个人备份，不代表最新全站数据；界面的植物 JSON 导出也不能代替分类、身份与全部照片的完整备份。

迁移时保留照片对象键中的账号前缀和植物/分类 ID。COS 保持私有，由服务端核验账号后读取；不通过公开桶解决图片访问问题。数据库和照片备份应有独立副本，并完成一次恢复演练。

## 上线与回退验收

1. 先做完整备份和测试环境导入，按表统计记录数量、按对象统计照片数量，并校验图片内容与引用。
2. 从无 VPN 的大陆移动网络与家庭宽带测试首页、开屏、登录、档案、分类、照片上传和读取。
3. 用两个独立账号验证相互不能访问档案、照片或分类参考图；确认原拥有者数据仍可由本人访问。
4. 验证多设备同步、版本冲突、状态日志、图片对比和桌面入口；静态资源加载不依赖 Google Fonts 或旧网站。
5. 切换前暂停旧站写入，做最终增量迁移，完成核对后将新站设为唯一写入入口。
6. 更新域名入口、登录回调、桌面链接与所需备案展示。旧站保留只读/维护提示与迁移前快照。
7. 若新站已经产生新记录，回退前先核对并迁回这些增量；不能直接恢复旧快照覆盖新数据。
