# 修复补充英文名时误报分类重复

主站：https://gloriouscarnivorousplants.top。

上一版在复用已有节点时，把新增中英文名称一并按“修改已有名称”拒绝。例如，原节点只记录了“植物界”，在英文栏补入“Plantae”也会出现“分类名称已存在，请在分类树中编辑中英文名称”，阻止整个档案保存。

## 本次行为

- 同一个层级的中文、英文是一个节点的两个名称，不会因为填写两种名称另建一层。
- 已有节点缺少一种名称时，可以在植物档案中直接补全并保存，不必先去分类树补译。
- 补全时保留原节点的主标识；共用名称保存为分类节点资料，其他同类植物再次编辑时可以自动复用已录入的名称，不重新翻译、不复制分类分支。
- 树节点从已有资料合并显示中英文，不因旧记录仍缺少英文而显示成两个节点。
- 原有非空名称确实不同，或中英文分别匹配了两个已有节点时，仍会拦截；提示会指出层级和冲突名称。需要改动已有名称、移动或合并分类时，应核对后通过分类树处理，不自动合并旧数据。
- 档案保存与共享名称补全在同一个 SQLite 保存点中提交；其中一步失败，两者一并回滚。保留照片、参考图、购入信息、坐标精度及另一套分类路径。
- 普通新建植物不会额外建立永久名称历史；只有实际补全的共用名称作为节点资料保存。没有在安装时批量转换或删除旧分类。

APG IV 中保留的传统层级与演化支显示规则沿用上一版，本包修复的是名称补全被误判的保存问题，不会根据分类学推断自动删改已有层级。

## 安装

下载[修复包](https://github.com/yunjunyisg/leaf-archive/releases/download/taxonomy-labels-v1.6.1/leaf-archive-taxonomy-labels-v1.6.1.tar.gz)，完整上传到 `/root/leaf-migration/` 后执行整段命令：

```bash
(
set -e
cd /root/leaf-migration
echo "213a611fb22e09e1915e8ead557bebed23c534a970563f10b241e25b469a16a4  leaf-archive-taxonomy-labels-v1.6.1.tar.gz" | sha256sum -c -
gzip -t leaf-archive-taxonomy-labels-v1.6.1.tar.gz
UPDATE_DIR=$(mktemp -d /root/leaf-migration/taxonomy-labels-verified.XXXXXX)
tar -xzf leaf-archive-taxonomy-labels-v1.6.1.tar.gz -C "$UPDATE_DIR"
(cd "$UPDATE_DIR" && sha256sum -c SHA256SUMS)
bash "$UPDATE_DIR/deploy/apply-standalone-update.sh"
)
```

包含当前程序及公开资源，复用并校验已安装的全球边界，不导入或替换数据库。若原来的编辑窗口仍有未保存内容，安装后可以先在该窗口重试保存，成功后再刷新页面或关闭重开软件，无需重装。如果仍被真实名称或上级冲突拦截，请先记录需要保留的输入，再按具体提示处理，避免刷新丢失草稿。

没有配置服务器执行连接，源码与修复包发布不代表主站已安装。

## 验证

122 项自动测试通过，包括同节点补全名称、主标识不变、旧中文路径与新中英路径合并为一个节点、不同节点的真实冲突、共享补译持久化、原参考图保留、存储失败同时回滚、并发补译不相互覆盖，以及普通新建不留下额外名称历史。

本地原生 Node HTTPS 程序在电脑和手机尺寸 Chromium 复现旧中文档案补充英文并成功保存，检查同类植物自动复用、树里只有一个对应节点、照片/日期/价格/坐标保留和真实冲突具体提示；无脚本异常。真实设备与主站需安装后验收。
