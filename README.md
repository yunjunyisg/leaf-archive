# 植藏 · 私人植物档案

中文植物收藏记录网站，支持检索、科属分类树、照片导入、植物档案与养护日志。

当前主站：[https://gloriouscarnivorousplants.top](https://gloriouscarnivorousplants.top)（个人档案和照片需要登录，并按账号隔离）。

后续开发、修复、部署和验收均以此主站为目标，代码继续同步到本私有仓库。旧托管站点仅保留迁移历史，不再作为默认发布目标。

## 功能

- 中文名、学名、收藏编号、来源编号、购入来源、价格与日期
- 产地、个体信息、简介、摆放位置、养护需求及备注
- 多张照片导入，卡片与列表视图，关键词检索与筛选
- 按日期排序的生长时间线，支持补录文字、多张照片和拍摄日期
- 选择两张生长照片生成 PNG 对比图，标注日期、收藏编号和间隔天数
- 养护日期、来源汇总与 JSON 档案导出
- 网站账号密码登录及自助注册，密码至少六位；新账号建立独立空白收藏
- 阿里云独立运行：SQLite 保存档案，私有目录保存上传图片；按账号隔离数据

## 开发与检查

需要 Node.js 24 LTS。

```sh
npm ci
npm test
```

`npm test` 会构建共用服务逻辑并检查账号隔离、注册登录、照片访问、版本冲突和地图边界传输。独立后台入口为 `standalone/server.mjs`；本机调试可使用单独的数据目录：

```sh
npm run build
SITE_ORIGIN=https://gloriouscarnivorousplants.top \
LEAF_DATA_DIR="$PWD/.local-data" \
PORT=3100 \
node standalone/server.mjs
```

后台只监听本机地址。完整浏览和登录须通过与 `SITE_ORIGIN` 一致的 HTTPS 反向代理，不能把纯 HTTP 本地访问当作安全会话验收。服务器安装和运行方式见 [阿里云部署说明](docs/aliyun-deployment.md)。`npm run dev` 与 `wrangler.jsonc` 仅保留旧运行环境的兼容预览用途。

## 目录

- [`plant-icons/`](./plant-icons/)：独立植物标识图库，含全部 83 张透明开场图及预览
- `public/`：页面、样式、交互脚本、示例照片与来源信息
- `standalone/`：当前主站的 Node.js HTTP 入口、注册登录、SQLite 和私有照片存储适配
- `worker/index.js`：共用页面与 API 逻辑，由独立运行层提供数据库和图片存储绑定
- `deploy/`：系统服务、反向代理参考配置与注册功能更新安装脚本
- `db/schema.ts`、`drizzle/`：数据库定义与迁移
- `scripts/build.mjs`：编译共用服务与浏览器资源，输出独立运行入口使用的服务模块
- `wrangler.jsonc`：历史托管环境的兼容预览配置

## 部署说明

当前目标为阿里云 ECS 上的 `gloriouscarnivorousplants.top`：Node.js 24 运行应用，SQLite 持久化档案，私有磁盘目录存储照片，由宝塔管理的 Nginx 提供 HTTPS 并反向代理到本机 3100 端口。服务和数据路径、安装步骤及验收要求见 [阿里云部署说明](docs/aliyun-deployment.md)。

仓库保存源码，尚无自动部署到服务器的流水线。提交到 GitHub、生成安装包、服务器安装与线上验收是分别进行的步骤；不能仅凭提交成功就声称主站已更新。后续更新只面向当前主站。`.openai/hosting.json` 和旧存储接口保留用于历史环境兼容，不决定当前发布目标。

历史个人植物记录与上传照片备份位于 `backups/personal/`，仅应保存在私有仓库。仓库不包含运行凭据或本地测试数据。示例照片及其署名、来源和许可信息见 `public/credits.json`；请遵守各照片对应的许可。

## 生长记录与对比图

打开植物档案，在“生长时间线”中选择日期、类型，填写文字或导入最多 6 张照片后保存。记录可以按日期升序或降序显示，旧记录保持兼容。已有档案照片的拍摄日期可在“编辑档案”中补填。

在“生长对比图”中选择两张不同照片，点击生成并下载 PNG。带日期的照片会按先后排列并计算间隔；无日期照片会明确标注。对比图在浏览器内生成，不会新增云端图片。

## 桌面快捷方式

网站侧栏的“添加到桌面”提供安装入口与设备操作说明，使用指定植物图标。Android Chrome 可安装或添加到主屏幕，iPhone/iPad Safari 使用分享菜单添加到主屏幕，电脑 Chrome/Edge 可安装独立窗口。实际安装需要在用户设备上完成。

Windows 可下载 `/downloads/leaf-archive-shortcuts.zip`，解压后运行“安装到桌面.cmd”。脚本只在当前用户目录保存图标、在桌面创建指向当前主站的快捷方式，不需要管理员权限；源文件位于 `desktop/`。其他系统使用浏览器安装入口。

快捷方式继续使用现有登录和云端数据，查看与保存档案需要联网。Service Worker 仅保存通用离线说明页，不缓存个人档案或照片。网站未接入 AI 生图 API。

## 多设备与多窗口同步

手机、电脑浏览器和桌面快捷方式访问同一网站，登录同一个账号后，共用云端植物档案、照片和生长记录。前台窗口每 15 秒读取最新档案，切回窗口或重新联网时立即读取；同一浏览器中的多个窗口通过通知立即同步。不同账号的档案继续隔离。

编辑表单和未提交的生长记录不会被自动刷新清空。保存与删除校验当前档案版本，其他设备已更新时会提示重新打开，避免旧内容覆盖新记录。旧档案首次保存时自动补上版本，无需数据迁移。断网时不会伪装保存成功，恢复连接后自动重试读取。

运行 `npm test` 验证跨入口读取、账号隔离、并发修改保护与自动刷新行为。

## 网站账号与微信接入状态

当前独立站使用网站专用账号密码，提供登录页 `/auth/local` 和注册页 `/auth/register`。新注册用户获得独立空白收藏，密码至少六位；注册功能是否已安装到服务器须以线上验收为准。网站账号会话使用安全 Cookie，令牌摘要保存在数据库中，七天有效，退出后撤销。

微信登录作为后续接入项，当前不对外宣称已开放。仓库保留微信开放平台网站应用扫码登录（`snsapi_login`），以及微信内公众号网页授权（`snsapi_userinfo`）。新微信账号独立保存数据，收藏编号可与其他账号重复；同一微信账号在多个设备使用同一份档案。

微信实际登录需要项目所有者开通对应权限，并在微信后台登记/校验回调域名。按 `.env.example` 的变量名，在托管平台服务端运行环境设置 AppID、AppSecret 和完整 HTTPS 回调地址。AppSecret 必须作为密钥存储，不放到网页、GitHub 或聊天中。当前前端隐藏微信入口；配置和联调完成前，不模拟微信登录。

- `WECHAT_WEB_APP_ID` / `WECHAT_WEB_APP_SECRET`：开放平台网站应用。
- `WECHAT_MP_APP_ID` / `WECHAT_MP_APP_SECRET`：公众号网页授权；用户须在微信中打开。
- `WECHAT_REDIRECT_URI`：当前网站域名下的 `/auth/wechat/callback` 完整地址，与微信后台登记保持一致。
- `TRUST_SITES_IDENTITY=true`：仅在原 Sites 托管中启用可信身份头，保留“原网站账号登录”及原拥有者数据。其他托管环境默认忽略此头，不能把客户端自报的用户 ID 当作身份。

微信授权 state 与当前浏览器绑定，10 分钟有效且单次使用。微信授权会话使用 Secure/HttpOnly/SameSite=Lax Cookie，数据库仅保存令牌摘要，30 天过期，退出即撤销。两个微信应用同属开放平台且返回相同 UnionID 时可共用账号；没有 UnionID 时按各应用 OpenID 隔离，既有账号冲突不自动合并。原拥有者数据不会自动迁移给新微信账号。

数据库新增身份、会话和授权状态表，由 Drizzle 迁移创建。`npm test` 使用模拟微信响应验证完整授权流程、会话撤销、跨账号读写与照片隔离；真实微信登录还需完成平台配置后联调。开放登录页不等于已解决中国大陆网络可达性，当前主站的网络、域名与实际功能仍需分别验收。

当前服务器程序包在构建后通过 `node scripts/package-standalone.mjs /绝对路径/leaf-archive-aliyun.tar.gz` 生成，包含独立运行层、共用服务模块、数据库迁移和部署参考。`npm run package:site` 仅保留为历史托管兼容命令。

## 独立分类树页面

分类树位于 `/classification`，首页侧栏保留入口，不再内嵌分类树。支持界、门、纲、目、科、族、属、组、系、种、变种、变型，允许跳过未填写的层级。未定种（sp.）、杂交种（×）与种并列；近缘种 aff.、近似种 cf. 为种下节点。相同分类路径的多个收藏个体会归入同一节点，旧档案按已填写的科、属和学名/名称继续显示。支持搜索完整分类路径、全部展开或收起以及点击查看个体档案。分类树读取当前账号的云端档案；示例档案可单独切换浏览。微信登录接入暂时暂停，页面隐藏微信登录入口，当前主站使用网站专用账号密码登录并保持账号隔离。

登录后可在分类树中“添加分类”或“添加下级”，无需先建立收藏个体。种、未定种、杂交种及种下节点的“参考图”入口可导入或移除 JPG、PNG、WebP；每张最多 8 MB，每个节点的参考图数量不限。导入后点击“保存分类”完成，参考图不混入个体档案照片。分类与参考图通过 `/api/taxa` 通过独立运行层保存到当前账号的 SQLite 记录和私有图片目录，支持多设备刷新与版本冲突保护，个人图片只能由所属账号访问。

新增/编辑植物时可填写完整分类信息、基础种名与鉴定类别；未定种可用 `某属 sp. 1` 等名称区分。选择 aff. 或 cf. 后填写对应鉴定名称，变种、变型字段自动隐藏。独立建立的分类节点与植物填写的完整分类路径一致时会合并显示。更新网站时需应用 `drizzle/0002_taxonomy.sql`；迁移只新增分类表，不修改已有植物与照片。

## 状态变更与生长线

每株植物档案提供“变更植物状态”，支持生长中、需关注、休眠中、已赠出、已死亡，可填写变更日期和备注。保存时同步更新当前状态，并在生长时间线自动添加“原状态 → 新状态”事件；通过“编辑档案”修改状态也会自动记录当天的变化。同一状态的重复保存不产生事件。状态与历史记录在一次带版本校验的数据库写入中保存，已有状态历史不会因后续编辑丢失。


## 世界产地地图

产地地图位于 `/origins`，侧栏新增入口。支持世界地图缩放、国家/地区选择和城市、区县等地名搜索；国家边界概览采用 Natural Earth，缩放后的底图及行政分区细节由 OpenStreetMap 提供。不同国家的行政层级、边界和地名覆盖程度不一致；不宣称已内置全球所有县市的完整矢量边界或名录。国家选择列表还包括地区及小型岛屿；较小地区可通过地名搜索进一步定位。

在新增/编辑档案的“产地与个体信息”中点击“地图标注产地”，搜索并确认地点、直接在地图上标点，或手动输入经纬度。位置精度可记录为国家、省州、城市、区县、乡镇或具体地点；行政区代表位置不作为精确采集点。点击“使用此位置”只更新表单，点击“保存档案”后才写入当前账号的云端数据。取消编辑不会写入标点。原 `origin` 文字保留，旧档案不会批量自动定位；地图列出待定位档案，可逐株核对。

地图按国家及已标注档案的省州、区县、城市筛选；点击标点查看该产地植物，点击具体地图位置可查询附近行政区；附近植物范围可选择 1、5、10、50 公里，默认 1 公里。档案详情提供返回地图入口。植物坐标保存于档案 JSON 的 `originLocation`，沿用原账号隔离、多设备读取和版本冲突保护。示例位置明确标为示例代表位置，不是采集坐标。

地名查询通过服务端转发至 [Photon](https://github.com/komoot/photon)，仅响应用户操作，不在输入时自动请求。全站共用数据库限流（至多约每 1.1 秒一次上游请求），相同查询缓存 7 天；查询需登录。公共服务可能限流或不可用，此时可手动标点及填写行政区。服务端可用 `MAP_GEOCODER_URL` 切换到兼容的 HTTPS Photon 实例。底图按实际视窗从 OpenStreetMap 加载，不做离线预取。地图软件和数据许可见 `/map-licenses.txt`。

发布时应用 `drizzle/0003_origin_map_cache.sql`，只新增公共地名查询缓存表，不改已有植物、分类、照片或身份数据。`npm test` 验证产地位置保存与移除、账号隔离、版本冲突、零度坐标、缓存与限流。当前主站由独立运行层维护 SQLite 迁移；后续更新和验证均面向阿里云主站。


### 小地名与产地精细定位

新增澳大利亚 GeoNames 地名快照，当前包含 215,386 条记录，覆盖聚落、宅地、农场、水体、山地等地物，按姓名及别名查询，并结合州与县名理解查询上下文。示例 `Kingston Rest`（GeoNames 8351675）位于 Western Australia / Wyndham-East Kimberley，地名代表坐标为 -15.98111, 128.4178，类别为 homestead。此坐标不是植物采集点，也不能直接等同于同名气象站或整个地产范围。

搜索结果会显示名称、坐标、地物类别和数据来源。选中后，在地图上显示小地名标签；保存档案时保留 `locality`、`featureType`、`sourceId`、`sourceUrl`，原有自由文字产地不受影响。底图没有印出名称的地点也能显示用户已选或已保存的标签。其他国家继续使用 Photon 在线地名服务；未收录的地点可手动填写“小地名 / 牧场 / 采集地名称”并输入实际已知坐标。搜索框也支持 `纬度, 经度`。

澳大利亚指定国家的地名库匹配不需要在线服务；世界范围搜索会合并当地快照与在线候选并按名称匹配程度排序，不能把附近的大城市自动当成目标小地名。在线服务不可用时仍返回本地匹配并说明状态。缓存键已升级，避免复用旧版空搜索结果。澳大利亚以外没有内置全量小地名库，不承诺全球小地点完整覆盖。

数据、快照校验值与更新方式见 [`data/gazetteers/`](./data/gazetteers/)；GeoNames 数据采用 CC BY 4.0，不保证完整性或测量精度。快照在服务器端按流检索，浏览器不下载全量地名文件。更新命令为 `python3 scripts/update-au-gazetteer.py`，不是用户查询时触发的批量下载。

### 分类与行政分区联动

参照用户视频，产地地图增加按种或按属切换的分类标签、稳定颜色图例、档案名称/编号筛选和行政区交互。国家、省州、美国县或澳大利亚地方政府区按当前筛选下的已定位档案着色；多个分类共有记录的分区显示斜纹。悬停显示分类和株数，点击分区筛选对应植物，再点击图例可进一步筛选分类。支持显示地理底图和重置分类与地图，现有 Kingston Rest 小地名检索、原始坐标和编辑保存流程保留。

这张地图展示已确认的档案产地分布，不自动提供或推断完整物种野生分布范围。未定位档案仍列出供人工核对。省州边界快照包含 4,584 个分区和 240 个国家/地区代码，县级矢量限美国与澳大利亚；缺少边界时仍可查看原始标点。边界概览不用于精确测量。国家精度不会自动推断省州，省州或城市代表坐标不会自动细分为县级分布；未匹配数量会在地图上说明。

边界在切换层级时按需读取站内 gzip 快照，无须额外在线地理服务。数据来源、许可、年代及更新脚本见 `data/boundaries/README.md`，网页许可见 `/map-licenses.txt`。地图分类和关联只在浏览器中读取当前账号档案，不修改账号隔离或批量改写个人记录。

### 按缩放自动细化着色

地图默认采用“自动随缩放”：远景着色国家，中景着色省州，近景着色美国县或澳大利亚地方政府区。Kingston Rest 的档案会随放大依次关联 Australia → Western Australia → Wyndham–East Kimberley；缩小后按相反顺序恢复。同一分类保持同一颜色，每次切换移除上一层填色，保留原始标点、分类筛选与搜索地点标签。尚未支持县级边界的国家在近景保持省州层级，不猜测更细区域。

下拉框仍可选择“国家 / 地区”“省 / 州”“区 / 县”手动锁定层级；选回“自动随缩放”恢复自动切换，重置地图也恢复自动模式。自动模式依据缩放级别和当前所选国家或地图中心判断，异步边界请求只显示最新层级。原有位置精度限制继续适用，不会因为放大就推断不存在的县级产地。

边界 HTTP 回归验证：站内 gzip 边界由 Worker 以 `encodeBody: 'manual'` 原样发送，防止运行时对已压缩数据再次 gzip；前端请求携带资源版本，避免继续使用旧压缩响应缓存。边界加载或 JSON 解析失败时持续显示错误及重试按钮，地图缩放不会覆盖错误提示，原始标点保留。`tests/map-http.mjs` 使用真实 workerd/Miniflare HTTP 传输验证浏览器一次解压后即可解析三套边界，不能只用 Node 的 `Response` 模拟替代线上压缩验证。

### 页面与地图性能

- 使用系统字体，不再通过阻塞 CSS `@import` 请求 Google Fonts。开屏在当前标签页会话中仅首次展示，地图与分类页跳过开屏，图片未完成时最多等待 2.5 秒。
- 省州边界按当前国家加载 `/map-boundaries/admin1/{国家代码}.json`，保持原快照的全部行政区和坐标。澳大利亚压缩数据为 25,745 字节，原全球文件为 2,085,183 字节；仍保留全球回退及美国、澳大利亚县级覆盖。
- 地图悬停只恢复当前分区样式，分区提示按需生成；缩放时复用未变化的标点和列表 DOM。地理底图仅在用户勾选后请求。
- 公共脚本、样式和标识支持内容 ETag 与 304 校验；个人档案、登录响应和照片仍不进入公共缓存。预览图采用延迟加载和异步解码，屏幕外卡片跳过绘制；搜索输入合并处理。
- `npm test` 包含真实 workerd HTTP 单次 gzip 解压、按国家边界完整性、公共缓存/未登录照片保护，以及国家→省州→县区→国家的着色与局部悬停恢复检查。上述字节数属于资源测量，不代表用户实际网络延迟。

### 阿里云独立服务器版本

独立运行入口为 `standalone/server.mjs`，需要 Node.js 24 LTS，使用持久化 SQLite 和私有照片目录；新用户可自行注册独立空账号，原档案账号由管理员明确绑定并保留原 owner，禁止信任外部 Sites 身份头。部署、最终数据导入和现有宝塔 Nginx 接入参见 [阿里云部署说明](docs/aliyun-deployment.md)。

`node scripts/package-standalone.mjs /绝对路径/leaf-archive-aliyun.tar.gz` 在构建成功后生成无需服务器端 npm 安装的程序包，不包含真实档案、照片或凭据。该命令不执行服务器部署，也不迁移 DNS。迁移后微信登录仍需另行接入。

历史迁移附件：`/migration-downloads` 在显式开启且未过期时，仅向原档案拥有者提供程序包和部署预演备份。附件分块保存在 R2 的 `temporary-migration-downloads/` 独立前缀中，不写入图片表、不进入植物照片导出范围，也不加入已生成的服务器程序包。支持私有流式下载、Range 续传与校验值展示；匿名和其他账号不可访问。上传密钥只在准备附件时短期开启，上传及完整下载校验后移除。迁移结束后清理附件对象及下载配置；它们不属于新主站的用户内容，后续工作不再默认更新旧站。

多人注册：独立站登录页可进入 `/auth/register`，新注册账号自动获得独立空白收藏并登录，不能指定或认领旧档案。账号不区分英文字母大小写，密码最低六位。已安装服务器可下载“多人注册功能更新包”，运行包内安装脚本；脚本验证模块、备份旧版本并重启后台，失败时恢复旧模块，不重导数据库。更新包可通过 `node scripts/package-registration-update.mjs /绝对路径/leaf-archive-registration-update.tar.gz` 重建。

## 管理员后台

当前主站的独立运行层为管理员账号仅提供数据统计、账号管理和全部用户植物地图，统一入口为 `/admin`；可查看用户列表、账号与活跃统计、档案和照片数据及存储占用，并可注销普通账号并删除其全部业务数据，或将密码重置为默认值；重置后强制用户先修改密码才能使用网站。管理员角色须由服务器管理员交互配置，不能通过普通注册获得；密码不写入源码。安装步骤、统计口径和权限范围见 [管理员后台说明](docs/admin.md)。

管理员功能是否已安装并创建账号，应以服务器实际验收为准。源码提交或更新包生成不等于服务器已创建管理员。

当前主站页脚备案号为 **蜀ICP备2026066760号**，链接工信部备案查询。服务器更新方法见 [备案号更新说明](docs/filing-update.md)。

普通用户可在顶部“注销账号”入口验证当前密码并明确确认，注销后删除自身档案、分类、坐标及照片，所有会话失效。安装方式见 [注销与数据删除更新说明](docs/account-deletion-update.md)。

## Windows 与安卓软件

首个应用版本提供 Windows 10/11 64 位便携程序及安卓 10 以上安装包，应用名称为“植藏”。两端连接当前主站，账号和云端档案与浏览器共用；需要联网。下载与构建说明见 [软件使用说明](apps/README.md)。

双端新增“我的”页面，可编辑显示用户名及私有头像，汇总本人购入总额和科属分类，集中提供退出账号与退出应用。手机顶部原生操作栏移除，点击“植藏”刷新。部署见 [用户页面更新说明](docs/profile-update.md)。

种级分类新增“杂交种（×）”，与种、未定种并列。可填写杂交名称或亲本组合，在分类树保存参考图，并在产地地图按独立分类分组。已有档案不自动重分类；更新方法见 [分类树更新说明](docs/taxonomy-update.md)。

分类树节点可直接编辑名称、层级及上级，也可删除整个分支；关联档案的分类随修改原子更新，删除分类后植物保留在“未分类植物”。节点操作保留账号隔离与快照冲突检查，错误不会导致部分写入。
