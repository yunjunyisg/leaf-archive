# 植藏 · 私人植物档案

中文植物收藏记录网站，支持检索、科属分类树、照片导入、植物档案与养护日志。

线上网站：https://leaf-archive-oct03.giving-rook-4847.chatgpt.site （需要以网站所有者身份登录）

## 功能

- 中文名、学名、收藏编号、来源编号、购入来源、价格与日期
- 产地、个体信息、简介、摆放位置、养护需求及备注
- 多张照片导入，卡片与列表视图，关键词检索与筛选
- 按日期排序的生长时间线，支持补录文字、多张照片和拍摄日期
- 选择两张生长照片生成 PNG 对比图，标注日期、收藏编号和间隔天数
- 养护日期、来源汇总与 JSON 档案导出
- Cloudflare D1 保存档案，R2 保存上传图片；按用户隔离数据

## 本地预览

需要 Node.js 22 或更高版本。

```sh
npm ci
npm run build
npx wrangler d1 execute DB --local --file drizzle/0000_harsh_ben_parker.sql
npm run dev
```

打开 Wrangler 输出的本地地址可浏览示例档案。保存个人档案的 API 需要认证用户身份：生产网站由 Sites 注入可信的 `oai-authenticated-user-id` 请求头。本地接口调试可以手动设置此请求头；自行部署时需要通过可信认证层设置，并过滤客户端伪造的身份头。

## 目录

- [`plant-icons/`](./plant-icons/)：独立植物标识图库，含全部 48 张透明开场图及预览
- `public/`：页面、样式、交互脚本、示例照片与来源信息
- `worker/index.js`：页面及 API，访问 D1 和 R2
- `db/schema.ts`、`drizzle/`：数据库定义与迁移
- `scripts/build.mjs`：打包 Cloudflare Worker
- `wrangler.jsonc`：本地预览配置

## 部署说明

原网站继续由 Sites 托管。此仓库保存源码；后续标识修改同时同步到 GitHub 和原有 Sites 线上网站。GitHub 本身没有自动部署工作流，发布仍通过 Sites 完成。`.openai/hosting.json` 保留逻辑存储绑定，不包含原网站标识；`wrangler.jsonc` 中数据库标识用于本地预览，自行部署时需配置自己的 D1、R2 和认证层。

个人植物记录与上传照片的本次备份位于 `backups/personal/`，仅应保存在私有仓库。仓库不包含运行凭据或本地测试数据。示例照片及其署名、来源和许可信息见 `public/credits.json`；请遵守各照片对应的许可。

## 生长记录与对比图

打开植物档案，在“生长时间线”中选择日期、类型，填写文字或导入最多 6 张照片后保存。记录可以按日期升序或降序显示，旧记录保持兼容。已有档案照片的拍摄日期可在“编辑档案”中补填。

在“生长对比图”中选择两张不同照片，点击生成并下载 PNG。带日期的照片会按先后排列并计算间隔；无日期照片会明确标注。对比图在浏览器内生成，不会新增云端图片。

## 开场植物图标

每次打开或刷新网站时，从 48 张根据用户植物照片绘制的手绘植物图标中随机选择一张居中展示，开场先渐显植物图标，再将文字从下方向上滑入，最后显示进入按钮。随后自动进入收藏页，也可点击按钮立即进入。支持手机布局与减少动态效果偏好。透明背景图标位于 `public/welcome/`，使用 WebP 压缩以加快加载；原始首张图标仍保留在 `public/welcome-plant.png`。
